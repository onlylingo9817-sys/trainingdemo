# 知识点模块 · 页面设计 v2（对齐收敛后的数据模型）

日期：2026-11-20
模型前提（已定稿）：车型树三层实体（通用 → 产品线 → 车系 → 版本，祖先覆盖后代）；知识点 `cars[]` = 应覆盖范围（只进分母）；资产 `carScope[]` = 实际适用（一切判定看它）；主讲解 = (知识点 × 车系) 关系；合成占位内容打标并排除出指标。
技术前提：无路由、`render()` 整页重绘、字符串模板、`data-act` 事件委托、`y_kp_ux.js` 已承载信息层级与空/加载/报错。

---

## 一、五条设计原则

1. **车型在每屏可见、可切**：顶部全局车型筛选器，所有列表、指标、矩阵跟着变。业务第一个动作一定是"看看 YU7 的"。
2. **诚实默认**：合成占位内容永远带 `◐` 标记；指标默认排除；右上角一个「含占位内容」开关切回对比——这个对比本身就是讲"现状被美化"的道具。
3. **矩阵代替列表**：凡是要回答"某车系行不行"的地方用「车系 × 资产」矩阵，不用平铺列表。
4. **判定只有一处**：`carScope`/`cars` 的匹配、分母分子、缺口原因，全部走同一个纯函数；页面只负责把结果排出来。
5. **只造两个新控件**：`carTreePicker`（车型树选择/只读 chips）和 `assetMatrix`（车系×资产矩阵）；其余全部复用现有表格、浮层、折叠。

## 三、两个核心组件

### 3.1 车型树选择器 `carTreePicker`

```
紧凑态（筛选条内）：  车型 [全部 ▾]        已选: SU7 Pro ×  YU7 ×
展开态（浮层）：
  ┌───────────────────────────────────────┐
  │ ☑ 通用（全部车系）                     │
  │ ☑ 小米  ├ ☑ SU7   ├ ☐ 标准版 ☑ Pro …  │
  │        └ ☑ YU7   ├ ☐ 标准版 …          │
  │ ☑ 澎程  ├ ☑ N70  └ ☑ N90               │
  │ 判定规则: 选车系即覆盖其下全部版本 ⓘ   │
  └───────────────────────────────────────┘
```

- 三种用法同一个组件：`mode=filter`（全局筛选）、`mode=multi`（表单 carScope）、`mode=readonly`（列表里的 chips）。
- 选父节点自动覆盖子节点；子节点全选时自动折叠成父节点（避免 `SU7, SU7 Pro` 冗余）。
- 浮层底部常驻一行求值规则说明，删掉 `car==='澎程'` 硬编码后，这里就是给业务的"真值表"。

### 3.2 车系 × 资产矩阵 `assetMatrix`

```
               SU7     YU7     N70     N90     说明
主讲解         ●       ●       ◐       ○      每车系至多 1 条
补充材料       2       2       0       0
核心题(≥3)     4       2⚠      3       0✗
过关演练(≥1)   1       1       0⚠      0⚠
判定           可考    差 1 题  占位    缺
```

- 格子状态：`● 已定稿 / ◐ 合成占位 / ○ 缺 / ◑ 待核 / ✕ 已过期`，颜色 + 形状双编码（色盲可辨）。
- 格子可点 → 浮层列出该格资产（标题、状态、carScope、主讲解徽标），并提供该格操作。
- 列头可展开到版本级（二级表），默认只到车系——避免 4×12 的组合爆炸。

```
┌ 知识点库 / 底盘与驾控 ────────────────────────────── [编辑] [发起评审] ┐
│ KP-PROD-05  底盘与驾控   产品知识·技能·P0   负责人 王x   结构已核       │

│               SU7        YU7        N70       N90     行说明          │
│ 主讲解        ●定稿      ●定稿      ◐占位     ○缺      每车系至多 1 条 │

│ 过关演练(≥1)  1 场       1 场       0 场 ⚠   0 场 ⚠                    │
│ 综合判定      可考        差 1 题    占位      缺                       │
├ [车系 × 资产] [关系图] [依据与时效] [变更留痕] ───────────────────────┤

└──────────────────────────────────────────────────────────────────────┘
右栏（320px）
  缺口清单（原因 chips，按车系分组）   [去补内容][去补题][去补演练]
  主讲解指派记录（谁、何时、换过谁）
  时效: 复核日 2026-12-31  剩 41 天   [登记复核]
```

关键交互：

1. **主讲解在矩阵里指认**：点「指派」列出候选（该点该车系下 carScope 命中的已定稿内容），选中即写入关系；已有主讲解时提示"替换为 X / 仅作补充材料 / 取消"。
2. **每车系至多 1 条**由数据层保证，界面上不出现"第二条主讲解"的按钮。
3. **展开到版本**：列头「SU7 ▾」展开 4 个版本，仅在版本配置真有差异时用（如 Ultra 专属卖点）。
4. 顶部「应覆盖（分母）」与资产 carScope 不一致时给黄条：「SU7 在分母里，但没有任何资产覆盖 SU7 → 缺口」。

## 七、技术落地约束（保证能在现有栈里做）

1. **只新增 2 个组件文件**：`src/scripts/z_car_ui.js`（carTreePicker / assetMatrix / 状态点），插在 `y_kp_ux.js` 之后、`f_rn.js` 之前；`npm run check` 的脚本数同步 +1。
2. **全局筛选状态** `UI.carFilter`（多值树节点），渲染前统一过 `filterByCar(rows)`；判定函数只写一份 `carCovers(nodes, car)`。
3. **矩阵与浮层**沿用现有 `data-act` 委托 + `drawerOpen`；不引入图表库、不做拖拽、不做级联下拉。
4. **口径一致性**：指标分子分母、缺口原因、矩阵格子颜色，全部从同一个 `kpAssetStatus(kp, series)` 返回，页面只做渲染。
5. **演示可信度**：`dist` 页面角落显示构建时间戳（E3），避免再次出现"打开旧包以为没改"。

## 八、不建议做（避免过度设计）

- 版本级组卷 / 版本级指标：只在详情矩阵展开看，避免 4×12 组合爆炸。
- 参数化题生成：Q7 已证只有 4–7 道，直接用 carScope 多选。
- 复杂车型编辑器（拖拽、版本对比图）：配置页用三列树 + 真值表就够。
- 在移动端展示车型矩阵：手机端只回答"我该学什么"。

### 9.3 两表共用规则

1. 长文本列单行截断 + hover 浮层，不做行内换行撑高。
2. 所有 chips 列最多 3 个 + `+N`，点 `+N` 开浮层。
3. 操作列 sticky 右固定；不加图标按钮，保持文字链。
4. 表头不排序的列不画箭头；已支持的排序（更新 / 引用 / 有效期）收进标题栏右侧下拉，不占列。
5. 窄屏（≤1100）：知识点库先隐藏「分类」列；内容中心先隐藏「负责人」列，其余保持。


### 9.4 口径级决定（不是实现细节，验收按此判）

1. **空车型 = 通用，必须显式渲染 `[通用]` chip，不允许留白。** 留白会被读成"未填 / 不适用"，而语义是"全车系"。列表、详情、浮层三处统一。
2. **有效期在「状态 · 上架」列画时效点**：绿 = 正常 / 黄 = 7 天内到期 / 红 = 已过期；具体日期放 hover。时效健康度是四指标之一，不能只藏在 hover 里。
3. **合成占位内容用 `◐` 标记并在指标分母外单列**（批次 2 起生效；本批只落 `●已定稿 / ○缺 / ✕过期` 三态，合成态等打标完成后再开）。
4. **列表默认零横向滚动**；12 列完整字段是技术视图，允许滚动。
5. **窄屏（≤1100px）**：内容中心让出「引用·使用 / 负责人」；知识点库只留「知识点 / 状态·完备 / 操作」，由 JS 分支决定列，不用 CSS 隐藏（避免列定义与隐藏规则冲突）。
