# 培训全链路闭环 Demo · 业务审计报告

> 审计对象：当前线上 Demo（v24.1，标签化整改后 + 审计修复）
> 审计时间：2026-11-16
> 审计结论已以代码形式落地：`tests/t24c.js` 9 项业务验收
> 审计方法：按“发现问题 → 形成课题 → 生产内容 → 审核上架 → 组织培训 → 学员学习/测评/演练 → 效果回收 → 调优”逐步走真实页面，并核对数据是否同源、动作是否落地、状态是否有业务含义。不是只跑自动化测试。

## 一、结论摘要

**能演示一条完整链路，但还不能证明这套系统在真实业务中创造价值。**

| 问题 | 结论 | 说明 |
|---|---|---|
| 业务能跑通吗？ | **部分能** | 课题→内容→上架→学习项目→学员学习/答题→效果页，页面与状态可以走通；但“问题→内容”的闭环存在断点，部分状态只是流程状态。 |
| 能发现问题吗？ | **能发现，但发现的是“知识点级薄弱”** | 14 个知识点被判定为集中薄弱，其中 11 个已有可用讲解；说明系统能发现“人没会”，但不能自动区分是内容问题、讲法问题、练习不足还是执行问题。 |
| 能解决问题吗？ | **只能解决“缺内容”这一类** | 缺讲解、缺题、缺演练可以补；但“有讲解仍薄弱”时，系统此前没有直接动作。本轮已补“指派补练包 / 建演练 / 生成课题”。 |
| 能提升员工能力吗？ | **有机制，但未被真实数据证明** | 学员答题/演练会进入证据流并改变掌握度；学习任务完成本身不改变掌握度。当前提升来自模拟数据和关键词规则，不能证明真实能力提升。 |
| 能创造业务价值吗？ | **未证明** | 有对照、相关性和“不作因果”声明；但效果页的主指标仍是过程/行为指标，个人级业务结果与培训的因果关系需要真实数据和更长观察期。 |
| 能让新人不用培训就会用吗？ | **比上一版好，但仍不够** | 页头「怎么用」、工作台分组、知识点按标签导航已改善；配置中心、效果口径、调优仍偏专业，区域老师/一线需要引导或培训。 |

## 二、实际走通的链路（已验证）

### 2.1 发现薄弱点

- 零售通诊断/练习/演练写入 `ansLog` 和证据流，掌握度由测评 + 演练 + 行为 + 人工评价合成。
- 知识点总览的“学员集中薄弱”由 `kpWeakList()` 现算，当前能识别 14 个知识点；工作台汇总为一条“14 个知识点讲解齐全但学员集中薄弱”。
- 课题池能从系统出题、对外洞察、自主提出三种来源形成课题，并带会话数、门店数、趋势和建议培训类型。

### 2.2 形成课题 → 生产内容

- 知识点的薄弱点可以“生成课题”，课题自动带入知识点、车型、区域、建议指标。
- 从课题新建内容时，会自动挂上该知识点，并带入车型。
- 内容能提交审核、审核通过、定稿、上架；上架后知识点“讲解”格变绿，学员端可看到。

### 2.3 组织培训 → 学员学习

- 新建学习项目可以选择课题、培训类型、覆盖区域、培训目标、学习节点，并提交到零售通。
- 提交时会检查“在途任务超限”，需要填写原因才能继续；这是有效的业务约束。
- 学员端能看到覆盖自己的学习项目，完成学习任务后后台进度更新为 100%。
- 学员答题/演练会写证据流，掌握度会变化（示例：K4 从 38 变为 43）。

### 2.4 效果与调优

- 效果页有就绪度、错题集、调优、前后对比；有“试点 vs 对照”和“只说明相关、不作因果”的声明。
- 调优有配置版本、观察期、回滚；改口径会重算就绪度，并提示“就绪度变化来自权重重算，不是学员突然变强”。
- 前后对比只有在创建 v2 后才出现双重差分，未创建时是空态引导，符合“不伪造前后对比”的原则。

## 三、审计发现的关键断点

### 3.1 “已闭环”不等于真实闭环（高优先级，本轮已加可见性）

当前有 6 个课题处于“已采纳/已闭环”，其中 **4 个没有任何内容**；1 个“已闭环”的课题（T2 国地补口径）既无内容、也无上架记录。

原因：课题的“已闭环”由项目结项回写，不要求有内容、上架、学员复测。结果是管理者看到“闭环”，但一线可能没有可学内容。

**本轮已补**：课题卡对“已闭环”直接显示四段证据：内容 / 已上架 / 学习项目 / 已复测·结项；缺一段就标“闭环证据不全”。T2 现在会显示“无内容、未上架”。这没有改变业务规则，但阻止了流程状态冒充业务闭环。

**建议**：把“已闭环”定义收紧为：
1. 有至少 1 条可用讲解（已定稿且已上架）；
2. 有学习任务 / 学员完成记录；
3. 有复测或行为数据；
4. 有项目结项结论。
否则最多叫“已立项/已交付内容”，不能叫闭环。

### 3.2 “有讲解但学员仍薄弱”缺动作（本轮已补）

审计时 14 个薄弱点中 11 个已有可用讲解，9 个既无演练、题也不足。系统此前能显示“缺题/缺演练”，但知识点详情没有“怎么补”，工作台也只汇总成一条，不能直接处理单个点。

本轮已补：
- 知识点详情新增“指派补练包 / 建演练 / 生成课题”；
- 知识点总览的薄弱表新增“建议动作”列；
- 指派补练包会生成学习包实例，并把未过关学员 MID 写入 `pack.mids`；学员端 `packsOf()` 已能按 MID 看到群组补练包。
- 已验证：K4 指派补练包覆盖 43 人，学员马俊在零售通能看到该学习包。

**仍需验证**：学习包目前仍是 Demo 状态机；学员点“去完成”只推进步骤，未和真实学习任务/零售通下发打通；真实下发需要后端任务系统。

### 3.3 “学习任务完成”不等于“能力提升”

验证结果：学员完成学习任务后，学习进度从 0/2 变为 2/2，但掌握度不变；只有答题/演练才改变掌握度。

这是合理设计，但页面对管理者没有讲清楚。建议在培训项目详情明确写：
- 学习完成率 = 触达/参与；
- 掌握度 = 测评 + 演练；
- 行为出现率 = 实战；
- 业务结果 = 锁单等。
不要用“完成率”替代“能力提升”。

### 3.4 效果指标容易被误读为业务结果

项目详情只突出主指标（如“关键词开口率 35.7% → 46.1%”），覆盖 4720 人、对照 4248 人，但主指标仍是语料行为指标，不是锁单/业绩。效果看板有三层，但项目详情只显示一层。

**建议**：项目详情默认显示三层指标卡：
- 学习层：完成率、测评正确率；
- 行为层：关键词开口率、行为出现率；
- 业务层：锁单、开单率（明确标注相关，不作因果）。
主指标只作为“培训目标”，不作为“业务价值”的唯一证据。

### 3.5 归因仍是演示级

- 当前相关性 r=0.36，属于弱到中等相关；试点锁单 7.9 vs 对照 8.1，差异很小。
- 这是“诚实的模拟数据”，不是真实效果。
- 前后对比的双重差分需要先生成 v2 才有；当前未生成时是空态，合理。
- 真实落地前必须确认：对照批是否同岗位/同入职周数、观察期是否足够、业务干扰是否记录。

### 3.6 角色权限与工作动线

- 总部培训部：完整动作，合理。
- 区域老师：仍有“内容中心/上架到零售通”等总部动作，是否符合区域权限需要业务确认。
- 老板：只有总览和效果，合理。
- 学员：学习、练习、演练、提升清单，主线清楚。

## 四、是否真的能创造价值

### 能创造价值的部分

1. **把“问题”变成可执行对象**：薄弱点 → 课题 → 内容 → 学习项目，减少了“知道有问题但不知道怎么落地”的断点。
2. **把“内容”与“学员”连起来**：内容挂知识点，学员诊断按知识点推荐，避免内容和培训两张皮。
3. **把“效果”拆成三层**：学习、行为、业务，且明确“相关不等于因果”，比只看完成率更诚实。
4. **标签化导航**：知识点、内容共用标签树，多车型/多业务分类可维护，适合真实备料场景。
5. **调优回路**：配置版本、观察期、回滚，能支持“效果不好时改什么”。

### 还不能证明价值的部分

1. **真实数据未接入**：所有个人数据、语料、业务结果都是模拟；无法证明锁单提升来自培训。
2. **演练评分是关键词规则**：不是 AI，不能代表真实沟通能力。
3. **学习包未真正下发**：目前只是 Demo 状态机，没有接零售通/学习任务。
4. **标签树刷新会还原**：没有持久化，真实运营无法长期维护。
5. **没有真人可用性测试**：所有验证都是脚本 + 截图，不能证明一线不用培训就会用。

## 五、建议的下一步（按价值排序）

1. **先定“闭环”的业务定义**：没有内容/上架/复测，不允许标“已闭环”。这是最便宜、最能提升可信度的一步。
2. **把“学员薄弱”做成可执行队列**：每个薄弱点必须能指派补练包/建演练/生成课题；本轮已起步，下一步接真实下发。
3. **项目详情默认三层指标**：学习、行为、业务分层展示，主指标不再单独代表业务价值。
4. **接一条真实数据链**：先接“学习完成 + 测评 + 演练”三类真实证据，再谈业务结果；否则调优只是模拟。
5. **做一次真人可用性测试**：找 1 位培训部 + 1 位区域老师 + 1 位一线顾问，从工作台开始走“发现薄弱 → 指派补练 → 学员收到”，记录卡点。
6. **标签树持久化**：接后端或至少 localStorage，否则运营维护的标签刷新即丢。

## 六、审计证据（可复跑）

- 完整链路：知识点 K4（6.6kW 外放电，43/43 人未过关）→ 生成课题 T10 → 新建内容 N140 → 定稿 → 上架 → 学习项目 → 学员学习完成 → 后台进度 100%。
- 掌握度：K4 学员答题后从 38 → 43（证据流 `S.ev.q` 与 `ansLog` 同步）。
- 薄弱点：`kpWeakList()` 当前 14 条；其中 11 条已有可用讲解。
- 课题闭环：6 个已采纳/已闭环中 4 个无内容；T2 已闭环但无内容/上架。
- 归因：r=0.36；试点锁单 7.9 vs 对照 8.1；效果页有“不作因果”声明。
- 角色：hq 完整菜单；region 仍可见内容/上架；boss 仅总览/效果；学员端有学习/练习/演练/提升清单。
