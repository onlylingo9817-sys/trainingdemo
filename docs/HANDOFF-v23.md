## 3. 已确认的产品决策（不要重新讨论）
1. **课题池是辅助入口，不强制**；区域老师可直接建项目，无需审批；**审核人默认本人**（预留可配置）。
2. **灰度** = 指定范围 + 分批 + 对照批（首批 = 评审团，由创建人选；对照方式 A），在项目层做批次下发；有「灰度对比」页签。不单独「下发话术」，话术走学习任务做灰度。
3. **内容性质只有 话术 / 课程**。话术 = 「图文」内容 + 话术字段。**【v19 修订】演练、题、考试不迁入内容中心，仍留在各自系统，只在「知识点管理」里登记并挂到知识点**（见第 9 节）。
4. **内容管理拆二级菜单**：「内容中心」（生产侧）+「零售通发布」（上架侧）。**双状态**：内容状态 草稿/审核中/已定稿/已归档；上架状态 未上架/待上架/已上架/已下架。
5. **学习任务只要求「已定稿」，不要求上架**；引用时**锁定内容版本**（`contentVer` + `snap`），内容改版后项目里提示「可更新」，由负责人决定。
6. 内容过期只下架零售通，不影响已引用的学习任务。
7. 课题 = 需求单，不是内容；「分析结论沉淀成内部知识」本期不做。
8. 学堂现有 6 条内容全部迁移为「已定稿 + 已上架」，不重新审核。
9. 一线投稿 → 下期；本期做「点踩带原因 + 纠错」反馈收件箱。结构化正文 + 素材引用，不做 AI 视频。
10. **本期不做**：错题集、销售画像、千人十面等。**【v19 修订】自适应学习（诊断→提升清单→学→练→过关→间隔复测）纳入试点；错题集、销售画像仍不做。**
11. 周/月效果报告属于「效果追踪」；通知与权限分配功能已删除。
12. 思路原则：**能复用现有功能就复用，目标贴合的合并进去，用一套规范、结构化的东西解决所有业务场景**。

## 5. 代码结构速查
- 全局状态 `S`（数据）/`UI`（视图态）/`C`（编辑中内容）/`F`（项目表单）/`R`（零售通端）/`ME`（当前学员）。
- 事件：点击委托 `data-act` → `A.<name>`；`data-wc` 走 change；`data-cf="a.b"` 走 input 绑定到 `C`（`setPath`）。
- 文件职责：`head.html` CSS；`a_core.html` 状态/默认内容 `C0`/`TAX0`；`b_pc1.html` 菜单+路由+规则说明；`c_form/c_pc2/d_pc3/e_pc4` 学习项目、报名审批、配置中心；`g_topic*` 课题池；`l_gray` 灰度；`m_report` 效果报告；`k_content/k2_edit/k3_import` 内容中心（列表、详情、编辑、导入）；`h_seed` 种子；`i_ops/j_boss` 运营与老板视图；`f_rn` 零售通端。
- 内容辅助：`cEnsure`（兼容迁移）、`qcheck`（硬规则拦提交 / 软提醒）、`cSweep`（到期下架、定时上架）、`topicContentState`（课题进度）。
- 对照真实产品（auto-college）：内容类型 图文/视频/PDF/外部链接；字段 讲师/封面(324×220)/标题(≤50)/可见范围/课程专题/内容分类/首页推荐/发布方式/权威；PPT、音频现有学堂不支持上传（Demo 标「需学堂新增上传」）。

## 6. 踩过的坑（避免重犯）
- **用 Python 改文件时，不要先 `open(f,'w')` 再读同一文件**——会清空。已因此丢过一次 k_content，靠上一版拷贝恢复。改动前先备份上一版 `src` 文件夹（v17/v18 即这样做）。
- CSS 类名易撞车（`.dh` 与零售通头部、`.fl`、`pchip` 都撞过）；新类名加前缀。
- 表格宽导致按钮看不到：外层 `.tw{overflow-x:auto}`，操作列 sticky，`.content{min-width:0}`；列表限制在 ~9 列。
- 单列表单比左右布局好编辑（用户明确反馈过）；表单用 `FR(label,ctl,{req,nw,h})`。
- 用户多次强调「要和当前产品形态结合」，新增能力先对照 auto-college 现有结构，别另起炉灶。
- 每个数据都要有来源、每个入口路径要清晰（报名审批/效果追踪/配置中心曾被指路径不清）。
- Mock 数据要全：每个页面都应有数据。

## 11. v19.1 四模块联动（内容中心 ↔ 知识点管理 ↔ 零售通发布 ↔ 零售通）
**一句话**：内容中心管"内容是什么"，零售通发布管"能不能被看到"，知识点管理管"该有什么、缺什么"，零售通管"谁在用、用得怎样"。状态沿链路往下传，使用结果回流发现缺口。
**主链路**：内容 草稿→审核→已定稿（挂知识点）→ 上架 → 零售通学习专区 / 提升清单"学一学"；学员点踩/纠错/诊断结果 → 回到内容的新鲜度和知识点管理的弱点人数 → 知识点管理生成课题 → 课题新建内容（自动带知识点）→ 闭环。
**规则**：知识点管理"讲解"格只认 已定稿且已上架且未过期 的内容；"新鲜度"格读 过期/即将到期/待处理反馈/点踩偏高；提升清单只出 启用且有可用讲解 的知识点。
**v19.1 补的 5 处（均为提醒/入口，不拦截）**：
1. 上架弹窗：内容没挂知识点→提示"不进完备度检查、提升清单推不到"，并给推荐一键挂载（`kpPubHint`/`A.kpPubMount`）。已挂载则显示挂在哪些点上。
2. 零售通发布列表（已上架/待上架/已下架/首页推荐位）新增"知识点"列（`kpCol`），未挂载标黄。
3. 知识点详情页新增"怎么补"：讲解变红/新鲜度变黄时，逐条给直达入口——去审核 / 去编辑 / 去上架（直开"发布到零售通"页签）/ 去续期 / 去处理反馈 / 去挂载 / 新建内容（`kpFix`）。
4. 学员掌握度回知识点管理：知识点详情页有"学员掌握度"卡；看板新增"弱点人数"列（未过关/已测）。
5. 看板顶部"学员集中薄弱的知识点"（已测≥3 人且未过关≥50%，演示阈值，显示前 5）→ 一键"生成课题"进课题池（`kpMkTopic`，同一知识点不重复生成，课题带 `kpId`）；课题点"生成内容"时新建内容自动挂上该知识点和车型。
**未做/留给下一步**：掌握度回流是演示数据，正式做由答题与演练成绩回写；"点踩原因按知识点汇总"未做（反馈仍只挂在内容上，可通过内容→知识点反查）；上架不强制挂知识点（只提醒，是否改成强制是产品决策，未定）。

## 15. v21 演练（情景演练的交互）进入知识点管理
**用户要求**：重构时把演练的交互也做进去。**我的理解**：演练不该只在知识点上"登记一行"，而要像题一样成为知识点下的一等资产，后台能建脚本，零售通学员能真的练一场。若指的是别的，请纠正。
**演练 = 挂在知识点上的资产**（`src/r_drill.html`，`S.drills[]`）：一个脚本由若干**回合**组成：客户说一句 → 学员用自己的话答 → 立刻评分、点评、给参考话术。状态：草稿 → 已定稿 → 已停用；定稿前硬检查（每回合要有客户的话、≥1 个必说点、≥1 个思路点、参考话术，不能带 AI 占位文字）。
**评分沿用现网话术演练三维度**（来自知识库《AI评分规则》）：知识正确 35 / 情绪安抚 15 / 思路正确 50，共 100，**通关线 60**；总分 = 各回合平均。
**★ 评分是示意**：真实系统由 AI 评分、语音对话。Demo 无法接 AI，用可解释规则代替——「必说点」命中比例 ×35；「安抚词」命中得 15（回合没写安抚词则不考、按满分）；「思路点」命中比例 ×50；命中依据是脚本里写的"点名=说法1,说法2"，回答里出现任一说法即算说到。**这决定了 Demo 的分数只能验证流程和界面，不能验证评分质量**。
**后台**（知识点管理 → 演练页签）：列表（练习次数/平均分/通关率，通关率<30% 且≥3 次标"偏低"）、脚本编辑页（多回合增删、必说点/思路点用"点名=说法1,说法2"每行一个）、「AI 从话术生成草稿」（只填参考话术，客户的话/必说点/思路点要人补，否则不能定稿）。知识点详情页新增"弹药 · 演练(本系统)"块；完备度"演练"格改读真实脚本，**技能型知识点没有演练会单独提示**。
**零售通**（对话式 `rDrill`）：提升清单里有演练的点出现「去演练」（技能型）/「演练一下」，与「做几道题」并列；学堂首页「AI 实战」入口指向提升清单。流程：说明页（场景/客户画像/通关线）→ 逐回合（客户气泡 → 输入 → 可点"看提示" → 提交）→ 本回合三维度得分 + 命中/未命中的点 + 参考话术 + 原话术链接 → 总成绩（通关/未通关、最需要加强的一项、掌握度变化）→ 再练一次。
**计入掌握度**：一场演练总分≥60 记为"对"，否则"错"，**与题共用同一套掌握度算法**（`S.ansLog` 里 `mode:'drill'`）；中途退出不记录。同一知识点再练时，**优先出没练过/没通关的脚本**。
**知识点上的登记**：演练不再手工"登记"（登记表只留清河考试）；"本月演练次数"是示意数据。
**种子**：5 个已定稿脚本（D1 价格异议 2 回合、D2 竞品对比、D3 国补地补、D4 展厅接待、D5 极致储物）+ 1 草稿（无回合，不能定稿）+ 1 停用；所有脚本的"必说点"取自来源话术原文。
**仍然没有**：语音/真对话、AI 评分、角色演练的"角色形象/背景/多轮自由对话"、限流并发（现网有）、下发任务（走学习项目节点）、演练排行榜。**"自适应学习包"作为学习项目节点、模拟考试仍未做。**
**体验任务**新增：后台"建一个演练"，学员"完整练一场演练"。


## 16. v22 架构重构（本轮最大的结构调整，**以本节为准**）
**问题**（用户反馈"课题池、内容中心、知识点、零售通发布很乱"，对照 v21 实测）：①"缺什么"分散在课题池/内容中心「待我处理」/知识点总览三处；②知识点页有 8 个页签，混着"看全貌 / 造弹药（题、演练）/ 治理"三类东西；③题和演练是"内容的一种"却放在知识点里；④课题↔知识点互相生成、箭头交叉；⑤菜单按名词分组，看不出先后；⑥"AI 演练剧本中心"和我们做的演练重复。
**原则**：一条主线（发现 → 备料 → 发布 → 实施 → 效果）；一个对象一个"家"；待办只有一处；回流只有一条通道。
**新结构**
- **菜单按动作排序**：工作台 / ① 发现（课题池）/ ② 备料（知识点 = 要备什么、内容中心 = 怎么造）/ ③ 发布（零售通发布）/ ④ 实施（学习项目、报名审批、入店辅导）/ ⑤ 效果（效果追踪）/ 系统（配置中心）。老板视角不变（只看培训总览、效果追踪）。登录后默认进**工作台**。
- **工作台**（`src/s_workbench.html`，`pgWorkbench/wbItems`）：五段主线卡 + 4 个大数 + **统一待办**（20 种：缺讲解、没有负责人、待我审核、一线纠错、点踩反馈、即将到期、待上架、新课题、课题待生产、学员集中薄弱、候选知识点、未挂载、缺题、题/演练待定稿、待审批…），按紧急程度排序（"紧急"= 学员现在就受影响），可按 发现/备料/发布/实施 过滤，每条有「去处理」落到具体对象。**原"内容中心 · 待我处理"页签已并入这里**；培训总览保留为"流程说明与验收清单 + 老板视图"。
- **内容中心 = 备料 · 怎么造**：页签「全部内容 / 导入 / 使用与反馈」。「全部内容」统一列出 **话术、课程、题、演练** 四种性质（分段切换 + 状态/知识点筛选 + 「未挂载」筛选 + 「高级筛选」进入话术/课程的完整筛选）；右上角「新增 ▾」选性质。题、演练的编辑页保存/取消后回到内容中心。（数据结构不变：话术课程 `S.contents`、题 `S.qs`、演练 `S.drills`，只是入口合一。）
- **知识点 = 备料 · 要备什么**：只剩 **总览 / 看板 / 候选 / 清河迁移** 四个页签，只做"盘点和治理"，不再生产内容。**题库、演练、未挂载内容迁到内容中心；「规则」迁到配置中心 → 「知识点规则」**。知识点详情页仍展示它名下的内容 / 题 / 演练（弹药）和"怎么补"。

### 17.3 关键设计(改代码前必读)
1. **同源**:`v23Mastery(mid,kid)` 是唯一的掌握度算法;`mCalc/mRefresh` 在学员有证据流时委托给它(零售通、知识点页、效果页同数);学员只有 `ansLog`、没有证据流时退回 v22 单来源算法(保证新学员与旧测试可用)。`v23RefreshAll()` 把派生值写回 `S.mastery`,**任何改配置/画像的动作后必须调用**。
2. **真实作答进证据流**:`v23Sync()` 在零售通答题/演练结算时把作答折算进 `S.ev`,否则"答对了掌握度却不涨"(曾踩坑)。

4. **配置即数据**:杠杆全部在 `S.cfg`;版本在 `S.cfgV`(`raw` 存完整快照,回滚按它恢复);回滚本身也生成一条记录,不抹历史。

## 18. v24 产品化整改(2026-11-16,以本节为准)

### 18.1 为什么改
v23 能跑通算法,但按产品经理视角存在四类硬伤:
1. **两套能力口径**:知识点页仍是「服务力/领导力/业务力/沟通力/技术力/执行力」,岗位画像却是「探需/卖点转译/顾虑解除」。
2. **页面不是按任务组织**:知识点「看板」第一屏是「学员集中薄弱」,一线来备料却先看到效果分析;导入功能根本不存在。
3. **多车型模型不成立**:`k.car` 只能选一个车型,同一卖点同时适用 N90 / 探索版只能复制;热力图只统计启用点,完备率几乎全 0,看不出哪款车缺什么。
4. **黑话与空状态**:"弹药""归属/上下文""事实型/技能型"外露;新手不知道先做什么、下一步去哪。

### 18.2 本轮的决策
- **能力只有 4 项,全站唯一来源**:`探需 / 场景化讲车 / 顾虑解除 / 带人辅导`。知识点、内容、岗位标准(原岗位画像)共用 `Dab` 维度,不再有六力。
- **知识点与车型是多对多**:新增 `k.cars: string[]`;旧 `k.car` 保留为首个车型兼容旧页面。通用车型的知识点计入每一款车。
- **完备率按车算**:「能上课」= 有负责人 + 有已上架且未过期的讲解。`车型 × 部位`矩阵直接显示每格「能上课 / 已建」;没有内容的格子显示「未建」。
- **知识点页按一线备料动线重排**:`总览`(缺口 + 下一步) → `知识点库`(筛选 + 批量指派/启停) → `批量新建`(CSV 导入 + 新车克隆 + 一个点多车型) → `候选` → `清河迁移`。学员薄弱移到总览页尾,只用于决定先补哪块。
- **工作台收敛待办**:停用且无负责人的点不再逐条产生「缺讲解」;同类的低优先级事项合并成一条汇总;默认只展示优先级最高的 25 条。待办从 64 条收敛到 31 条。
- **导航与文案更业务化**:菜单改为 `发现问题 / 准备内容 / 上架到零售通 / 组织培训 / 看效果`;「弹药」改为 `讲解 / 测评题 / 情景演练`;「事实型/技能型」界面显示为 `产品知识 / 销售动作`;「归属/上下文」改为 `归类项 / 筛选条件`。
- **新增常驻「怎么用」**:页头按钮按当前页面给一句「这页做什么、下一步去哪」,不依赖首次弹窗。

## 20. v24.2 一门课程覆盖多个知识点（2026-11-16）

### 20.1 问题
内容原本已经支持 `kps: string[]`，但所有挂载被同等当作“这条内容讲了这个知识点”。一门“新车总览”课程挂 10 个知识点时，会让 10 个点的「讲解」都变绿，完备度被高估；但课程可能只是每点提了一句。

### 20.2 决策
- 一条内容增加 `mainKp`（主讲解）和 `kpRole: {知识点id: '主讲解'|'提及'}`。
- `kpMounted(k)` 只返回主讲解（用于「讲解」完备度、学员可学内容、推荐与出题来源）。
- `kpMentioned(k)` 返回提及（用于检索、关联、内容覆盖展示，不计入完备度）。
- 老数据没有 `kpRole` 时按“主讲解”兼容，不改变历史完备度。
- 编辑页支持切换主讲解；上架弹窗、一键挂载、内容编辑页三个入口都会写入角色。

### 20.3 验证
- `tests/t24d.js` 6 项：多挂、角色保存、主讲解计入完备度、提及不计入、详情标注、编辑页可切换。
- 示例：课程同时挂 K4 / K18，主讲解 K4 使 K4 可用讲解 +1；K18 只增加提及，不改变其完备度。

### 20.4 老数据兼容
老内容没有 `kpRole` 时，装载时把已挂知识点全部按“主讲解”处理，保持历史完备度不变；编辑一次后就可以明确切主讲解 / 提及。

### 20.5 仍未做
- 还没有“章节级”映射（课程第 1 章讲哪个点、第 2 章讲哪个点）。当前是整条内容一个主讲解 + 多个提及。
- 学员学完课程本身仍不直接改变掌握度；掌握度要靠题/演练证据。这是有意的，避免“看完课=会了”。
- `kpMentioned` 目前只用于展示，尚未用于“推荐课程给该知识点的学员”；下一步可做。

  - 链路检查的每条缺口都有“去挂知识点 / 去设主讲解 / 去补标签”直达。
- **知识点详情**：标签建议从大块卡片改为字段级小卡，采纳直接写回该知识点。
- **全局 AI 检查**：新增最近采纳 / 忽略留痕和“查看全部留痕”；明确标注当前是规则模拟而非真实大模型。
- **单页引导**：每页顶部说明“先做什么”，并增加“为什么这样建议”解释入口。

### 23.2 入店辅导：从“工单卡板”升级为“辅导项目”
来源文档：`https://mi.feishu.cn/wiki/GWoRw4arQij0QukJocwcxDgGnre?from=docs_feed_inlark`《入店辅导五维度提炼参考》。

原实现只有“触发 → 派单 → 到店 → 复测”四列卡板，不能承载文档要求的“学、练、检、用、馈”，也没有日/周/月反馈和真正的复测结案。本轮重构为：

- **六步项目状态**：触发 → 计划 → 到店 → 陪跑 → 复测 → 结案。
- **学**：关键岗位、产品知识、销售流程、标杆参访，按门店短板勾选。
- **练**：产品强化、政策权益、话术工具、动作固化，不贪多。
- **检**：入店前检核 + 辅导中检核（运营 / 能力 / 意愿维度），至少 2 项 + 一条真实记录才能进入陪跑。
- **用**：跟踪留资率、首触率、排程试驾率、HAD 试驾率、试驾质检达标率、心愿单保存率、试驾满意度等指标。
- **馈**：日 / 周 / 月反馈各留一条；日看动作、周看趋势、月看结果，并提示缺哪一类反馈。
- **复测**：填写辅导后数值和结论，系统计算变化并给出“结果有改善 / 幅度小 / 没有改善”的解释；结案必须写复盘和可沉淀动作。
- **AI 辅助**：总览新增「先跟哪家店」，按阶段、缺失反馈、是否已复测排序，并说明依据；不自动推进任何状态。
- **证据链**：从项目结项转入时保留项目、指标、辅导前值、目标等证据；详情页显示“触发证据”。

### 23.4 反思：AI 还能更“牛”的地方
- **从“推荐”走向“陪做”**：下一步不是再加推荐按钮，而是让 AI 在用户卡住时给“一屏可执行的 3 步”，例如“先补这条讲解 → 再挂知识点 → 再上架”，并能在完成后自动核对结果。
- **课程级理解**：当前课程解析基于标题 / 关键词规则，后续应把章节、案例、互动、练习、图片说明一起做结构化理解，而不是只生成课程骨架。
- **反馈闭环**：AI 建议被忽略的原因应可采集（不相关 / 不准确 / 已存在 / 暂不需要），用于改进推荐，而不是只记“已忽略”。
- **入店辅导的下一步**：把“日 / 周 / 月反馈”接成真实待办和通知；把复测结果自动回写项目效果；把有效动作真正沉淀到内容中心 / 知识点，而不是只打标记。
- **新人可用性**：当前靠页面引导和字段级提示降低门槛；下一步应做 3 分钟首次使用路径、空态示例和“我卡住了”入口，而不是假定用户会读所有说明。
