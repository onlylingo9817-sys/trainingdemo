# 知识点模块：架构现状与问题清单（供外部讨论）

日期：2026-11-23
覆盖范围：学堂后台「知识点」5 个页签 + 知识点详情 / 表单；内容中心（列表 / 详情 / 编辑）；配置中心里知识点相关配置。
数据全部来自当前 Demo 实测，不是估算。

---

## 0. 先看三个数字

| 指标 | 界面显示 | 排除「合成占位」后 |
| --- | --- | --- |
| 覆盖度（SU7 Pro · P0 口径，分母 33） | **94%** | **24%** |
| 可授课率 | 94% | 24% |
| 可考核率 | 36% | 36% |

原因：68 个知识点里有 **34 个的「主讲解」是系统自动合成的占位稿**（`N_V12_*`，正文只有「1. 定义 / 2. 关键讲法 / 3. 常见错误 / 4. 练习」四行模板）。真正有真实讲解的知识点只有 **15 / 68**。

> 这是当前最需要先说清的口径问题：**对外讨论前必须先声明「含/不含合成内容」**，否则大家在讨论一个虚高的覆盖率。

## 1. 架构现状

### 1.1 运行形态

- 纯前端 Demo：无构建步骤、无第三方依赖、无后端；数据存浏览器 `localStorage`（键 `trainingdemo.save.v1`，白名单 23 个字段）。
- 单页应用：`src/index.html` 顺序加载 **35 个脚本** + 2 个 CSS；无路由，`UI.page` 决定渲染哪个页面，`render()` 一次性重绘 `#main`，模板是字符串拼接。
- 交互：全站事件委托 —— `data-act`（点击）、`data-wc`（change）、`data-kf`/`data-cf`（表单输入）。
- 演示数据：确定性生成（同一天打开数字一致）；`dist/培训全链路闭环_Demo.html` 是给外部分享用的单文件构建产物。

### 1.2 分层与「覆盖层」机制

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 内核 | `a_core.js` | 工具、全局 `S`、存储、toast、弹窗 |
| 页面 | `b_pc1 / c_pc2 / c_form / d_pc3 / e_pc4` | 工作台、内容、项目、效果、配置中心 |
| 内容与资产 | `k_content / k2_edit / k3_import / p_quiz / r_drill` | 内容中心、编辑、导入、题、演练 |
| 知识点 v1 | `o_catalog / x_taxonomy` | 旧知识点页面与 v1 标准库（部分已被覆盖） |
| 知识点 v1.2 | `x_kp_v12.js` | **覆盖层**：68 条标准库、字典、四指标、锚/练分流、UI 覆盖 |
| 知识点 UX | `y_kp_ux.js` | 信息层级、空 / 加载 / 报错、表单校验、补学任务页 |
| 列表表格 | `z_tables.js` | 车型 chips、时效点、点阵、内容中心统一列表、知识点库 6 列 |
| 评审 | `review_gray.js` | 评审单、投票、代录、超期 |
| 零售通 | `f_rn / w_rn_extra` | 手机端 |

**关键机制：同名函数「后加载的生效」。当前有 42 个名字被覆盖定义**：

| 最终生效文件 | 覆盖定义数 |
| --- | --- |
| `x_kp_v12.js` | 18 |
| `y_kp_ux.js` | 15 |
| `z_tables.js` | 8 |
| `g_topic3.js` | 1 |

风险：改到被覆盖的旧定义会「改了不生效」，历史上已发生过多次（交接文档 §34 记录删过一批死代码）。新增功能必须放对层：业务规则进 `x_kp_v12.js`，展示交互进 `y_kp_ux.js`，列表表格进 `z_tables.js`。

### 1.3 数据模型（当前）

```
课题 topics ──→ 知识点 KP ──→ 补学任务 tasks（人 × 点 × 版本）
                   │
                   │ 多对多（content.kps[] + kpRole 按点设用途）
        ┌──────────┼──────────────┐
        ▼          ▼              ▼
    内容 contents   题 qs（单归属）  演练 drills（单归属）
   （课程41/话术47）  （130）        （23）
```

| 实体 | 关键字段 | 与车型的关系 |
| --- | --- | --- |
| 知识点（68） | `code`、`name`、`one`（一句话定义）、`domain` 知识域、`ability` 能力项、`sellpoint` 卖点分类、`typeV12` 类型、**`cars[]` 适用车型**、`roles[]` 岗位、`batch` 学习阶段、`stage` 业务环节、`pri` 优先级、`assess{}` 考核规格（核心题/练习/演练/过关线/有效期）、`owner`、`st` 启用状态、`statusV12` 依据核对状态、`pre[]/rel[]` 关系、`reviewDue`、`srcDoc` | **有**：通用 42 / 车系 15 / 产品线 8 / 车型 2 / 多车系 1 |
| 内容（88） | `kind`（课程/话术）、`kps[]`、**`kpRole{}`**（每个点的用途：主讲解/补充材料）、**`mainKp`（单值）**、**`car`（单值，不参与判定）**、`st`、`pubSt/pubVer`、`expire`、`vers[]` | 有单值 `car`（25 条非通用） |
| 题（130） | `kp`（单归属）、`role`（锚题 60 / 练习 70）、`type`、`stem`、`opts`、`ans`、`why`、`src`、`st`、`version` | **无** |
| 演练（23） | `kp`、`role`（锚定/练习）、`name`、`scene`、`persona`、`turns[]`、`src`、`st` | **无** |
| 车型字典 | 4 车系 + 12 个可下单版本 + 通用车型（两层树，没有「产品线」实体层） | — |

车型求值规则（`kpV12CoversCar`）：通用 = 全部 12 版本；车系（SU7）= 其下 4 版本；「产品线」写法实际是「澎程 N70 + N90 两条车系一起选」；版本 = 仅该版本。判定函数里另有 2 条硬编码特例（`car==='澎程'`）。

### 1.4 指标口径

| 指标 | 分母 | 分子 |
| --- | --- | --- |
| 覆盖度 | 岗位 × 车型 × 学习阶段 × P0/P1 命中的知识点（SU7 Pro + P0 = 33） | 该点有「主讲解」且已上架、未过期 |
| 可授课率 | 同上 | 有主讲解且依据核对状态不是「内容待核」 |
| 可考核率 | 同上 | 核心题 ≥ N 且（需要时）过关演练 ≥ 1 |
| 时效健康度 | 有主讲解的点 | 未过期、未超复核日 |

每车型应覆盖的知识点数：SU7 51–52、YU7 50、澎程 50–51（12 个版本共 606 对）。

## 2. 遇到的问题

### A. 指标真实性（最高优先）

| # | 问题 | 证据 |
| --- | --- | --- |
| A1 | 34 条合成占位主讲解把覆盖度从 24% 抬到 94% | 排除 `N_V12_*` 后：覆盖 8/33=24%、可授课 24%、可考核 36% |
| A2 | 合成内容是「看起来每个点都有讲解」的来源 | `kpV12Content()` 在知识点没有主讲解时自动生成一条模板内容 |
| A3 | 界面与文档口径未声明排除合成 | 总览未提示「含占位」；对外汇报容易误读 |

### B. 车型维度缺失

| # | 问题 | 证据 |
| --- | --- | --- |
| B1 | 题、演练完全没有车型字段 | 题 0/130、演练 0/23；而 **47 道题面提到具体车型**（18 道是锚题），会被当成全车型通用题 |
| B2 | 内容有 `car` 单值但不参与判定 | 覆盖度只看「该点有没有主讲解」，不看这条讲解讲的是哪台车 |
| B3 | 指标不按车型求交 | 同一知识点对不同车型的差别只在「在不在分母」，分子逻辑相同 |
| B4 | 抽题不按车型过滤，会串卷 | 诊断抽题池 48 个点（不按人/车型过滤），前 10 人诊断卷 10/10 含澎程专属题 |
| B5 | 车型只有两层树，没有「产品线」实体 | 「产品线 8 条」实际是澎程两条车系一起选；判定函数有 2 条硬编码特例 |
| B6 | 人没有「在售车型」字段 | 人员 12 个字段无车型；项目覆盖只按区域/岗位 |

### C. 口径与主讲解

| # | 问题 | 证据 |
| --- | --- | --- |
| C1 | 一条内容只能给 1 个知识点当主讲解 | `content.mainKp` 单值；一条覆盖 5 个点的全系讲解只能算 1 个点 |
| C2 | 一个知识点允许多条主讲解，没有校验 | 判定用 `find` 取第一条，界面不拦 |
| C3 | 主讲解过期/下架没有接任机制 | 该点立刻变「缺讲解」 |
| C4 | 一个点无法表达「SU7 一条、YU7 一条」 | 现在只能靠按车系复制知识点来绕（见 D1） |

### D. 知识点结构

| # | 问题 | 证据 |
| --- | --- | --- |
| D1 | 存在 9 对「同一学习结果按车系复制」 | 例：`KP-PROD-SU7-05 底盘与驾控` / `KP-PROD-YU7-04 驾控与底盘`；另有外观、续航、座舱、安全、车型定位等 |
| D2 | 真实内容严重不足 | 真实主讲解 15/68；校验 0 error / **48 warn**（缺讲解、缺考核规格、时效待处理） |
| D3 | 知识点关系像自动生成 | 前置 62 条、相关 62 条，68 个点里 62 个都有前置，图谱几乎全连通，信息量低 |
| D4 | 适用范围五种粒度混用 | 通用/车系/产品线/车型/多车系，同一层语义不统一 |

### E. 内容中心与交互

| # | 问题 | 证据 |
| --- | --- | --- |
| E1 | 标签体系数据为空但 UI 仍占位 | 内容带标签 0/88、知识点 0/68；标签树 42 个节点点了必定空列表（已止血为说明条） |
| E2 | 两套列表（简版/高级）曾并存 | 列不同、筛选不共享；已合并为单列表，入口统一映射到 `UI.sel.cq` |
| E3 | 内容编辑表单与知识点表单范式不一致 | 知识点有吸顶标题/分区导航/错误摘要；内容编辑是 3 张长卡 + 5 个并排动作 |
| E4 | 题/演练混在内容中心列表 | 一个列表里同时有内容、题、演练，行的字段能力不同（题没有有效期、内容没有题型） |

### F. 架构风险

| # | 问题 | 证据 |
| --- | --- | --- |
| F1 | 覆盖层机制脆弱 | 42 个名字被覆盖定义，改错位置静默不生效；历史上发生过 |
| F2 | 无模块边界 | 35 个脚本按加载顺序耦合，同名全局函数靠先后顺序决定行为 |
| F3 | 两套入口 | `src/` 开发、`dist/` 单文件交付；本轮出现过「打开旧 dist 以为没改」 |
| F4 | 全量同步渲染 | `render()` 整页重绘，列表 241 行也全量重算；无异步加载（加载态只接到批量导入读文件） |

## 3. 需要带出去确认的问题

> 按「找谁问」分组。每题都写了「为什么问 / 不同答案的后果」。

### 3.1 找业务（培训口径负责人）

**Q1. 合成占位内容是否从指标里排除？**
排除后覆盖度 94%→24%。这是对外口径问题，不是技术问题。
答「排除」→ 所有汇报数字重出；答「含」→ 需要标注占位比例。

**Q2. 驾控与安全是一个知识点还是两个？**
建议两个（考核结果不同）。若业务认为一个，A3 合并范围要扩大。

**Q3. 9 对疑似按车系复制的知识点，哪些合并？**
清单已出（底盘、外观、续航、座舱、安全、车型定位 + 澎程 3 组）。合并后一条知识点下按车系维护多条讲解。
答「不合并」→ 多车型讲解只能靠复制知识点，维护成本翻倍。

**Q4. 一条讲解内容能否同时是多个知识点的主讲解？**
现状：不能（`mainKp` 单值）。一条全系讲解覆盖 5 个点，只有 1 个算有讲解。

**Q5. 一个知识点每车系允许几条主讲解？谁定默认、谁维护？**
建议：每车系至多 1 条，多条时设「默认」。

**Q6. 主讲解过期/下架后如何交接？**
建议：临期预警生成待办；下架且无接任 → 降级为补充材料并进缺口。

### 3.2 找内容/题负责人

**Q7. 题和演练要不要绑车系？绑到车系还是版本？**
47 道题面提到车型（18 锚题）。建议绑车系（版本级只在详情看），避免 4×12 组合爆炸。
答「绑版本」→ 题量要按版本拆，题库规模上升。

**Q8. 政策类 30 天复核现在有人执行吗？要不要 SLA？**
现状：只有字段 + 校验提示 + 筛选视图，没有提醒/升级。

### 3.3 找数据 / 组织（人员主数据）

**Q9. 有没有「门店 → 在售车型」或「人员 → 在售车型」数据？**
现状：人员无车型字段，项目覆盖只按区域/岗位。补学任务要不要按在售车型过滤，取决于这个数据是否存在（6 家门店可先人工维护）。

### 3.4 找技术负责人

**Q10. 覆盖层机制是否长期保留？**
42 个覆盖定义，改错位置静默失效。可选：① 保留（成本低）② 按职责拆模块去覆盖 ③ 迁构建/框架。

**Q11. 是否引入数据访问层 / 真实后端？**
现在所有数据在 `S` + localStorage；若要接真实接口，建议先收敛一层 `data API`，页面不改。

### 3.5 项目管理

**Q12. 决策人与时间点？**
三项需要分别拍板：① 哪些知识点合并 ② 讲解按车系还是按版本 ③ 补学是否按车型过滤 —— 通常不是同一个人；另外是否有硬截止（新车上市/季度考核）。
