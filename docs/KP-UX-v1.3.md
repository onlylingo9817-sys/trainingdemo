# 知识点模块 UX 改版 v1.3（2026-11-20）

范围：学堂后台「知识点」一级菜单下的 5 个页签（总览 / 知识图谱 / 知识点库 / 候选 / 补学进度）、知识点详情、知识点新增与编辑表单。
目标：信息层级、操作路径、表格与表单交互、空 / 加载 / 报错状态。风格按「简约商用」：少装饰、统一控件、一屏一件事。

改版只动展示与交互，不改知识点数据模型、四指标公式、评审引擎和业务规则（见 `HANDOFF-v23.md` §17 / §39 / §40–42）。

---

## 1. 诊断：改版前的问题

### 1.1 信息层级

| 问题 | 具体表现 | 影响 |
| --- | --- | --- |
| 页面顶部堆了三层说明 | 全站横幅（`aiPageGuideHtml`）+「数据来源」蓝条（`srcBar`）+ 口号式副标题 | 第一屏被解释文字占掉，看不到数据 |
| 横幅与页面不符 | 候选、补学、图谱页都显示「先看总览的四指标」；新增表单显示详情页的「先看这个点能不能上课」 | 说明等于噪音，用户学会忽略它 |
| 开发口径上屏 | 「分母应为 33」「数据校验 0 error / 48 warn」「内容待核进分母、不进分子」「v1.2 总览：…」 | 业务看不懂，像是在看测试报告 |
| 两个入口同一份清单 | 「知识点 → 知识点库」与「配置中心 → 知识点库 v1.2」都列 68 条 | 不知道哪个是准的 |
| 详情页三处重复 | 标题芯片、右栏「这个点教什么」、右栏「基本信息」重复类型 / 车型 / 域；「怎么补」与三个资源卡按钮重复 | 一屏信息密度低，主次不分 |
| 「学员掌握度」位置靠前 | 夹在「能不能上课」和资源清单之间 | 先看效果、后看资料，顺序与工作流相反 |
| 总览八张卡片平铺 | 4 个指标 + 时效 + 内容待核 + 补学 + 校验 | 没有主次，口径选择器埋在中间 |

### 1.2 操作路径

| 问题 | 具体表现 |
| --- | --- |
| 候选确认是断点 | 「确认新增」直接 `push` 一个知识点：无编号、无知识域、无能力/卖点、无岗位、无考核规格、停用、无负责人；绕过新增表单的全部校验和 AI 评估 |
| 候选重复判断失效 | 提示的「相近知识点」是 v1 旧名（长续航与补能 / 辅助驾驶与主动安全），v1.2 里不存在；「金融方案讲解」已有同名点却只能新建 |
| 详情补资源入口重复 | 「怎么补」和资源卡各有「新增题目 / 新增演练」；两处都要维护 |
| 翻页与列表脱节 | 「上一个 / 下一个」按全库 id 顺序翻（`S.kps`），从筛选后的列表点进来会翻到无关点 |
| 补学进度只能看 | 无筛选、无催办、无关闭，人和知识点都不能点 |

### 1.3 表格

- 知识点库前 10 行状态一模一样（红绿橙橙 + 缺口），没有排序依据，四格圆点无图例。
- 候选表最后一列被裁（列宽不受控）。
- 表格首列贴左边框；热力表格子尺寸不一、不可点。

### 1.4 表单

- 产品知识的「卖点分类」「能力项」默认就填好了第一项，知识域、类型、阶段、优先级也有默认值 → 不动手也能保存，产出错误分类。
- 保存失败只弹一条 toast，不指出哪个字段、不定位。
- 无分区导航；吸顶工具栏是空白条（只有取消 / 保存），看不出在编辑什么。
- 行内输入框（其他系统测评、题数、车型名、过关分数）是浏览器默认样式，与其它控件不一致。
- 「内容审核状态」与内容中心的审核同名不同义。

### 1.5 状态与数据可信度

- 补学任务状态写死：3 条「逾期」但截止日未到，5 条已过截止却仍是「未读 / 已读 / 已确认」。
- 总览「补学任务 8/28 · 人员 41」——28 条任务不可能来自 41 人。
- 详情「已测 41 人、平均掌握度 66」但该点核心题 0 道、演练 0 场。
- 空状态只有一句灰字；渲染出错直接白屏，无兜底、无重试。

### 1.6 一致性

- 「批次 / 建议学习阶段」同一字段两个叫法；「知识点库 v1.1 / v1.2」两处叫法。
- 标签体系已取消，详情页仍给「建议补这些标签」。
- 同一知识点状态有「是否启用 / 依据核对状态 / 评审状态」三套，界面上没有区分说明。

## 2. 改版方案

### 2.1 设计原则

1. **一屏一个任务**：先看结论，再看缺口，再看明细；解释文字收进「怎么用」。
2. **状态由数据推导**：逾期、可否上课、能不能考核，一律由数据判定，不写死、不在界面写开发口径。
3. **同一件事一个入口**：缺口只在「怎么补」汇总，资源卡只负责查看和新增；候选只走新增表单一条路。
4. **可点即入口**：表格行、热力格、账号、知识点名都可点进对应对象。
5. **异常有出口**：空、错、加载三种状态都有标题、说明和一个下一步动作。
6. **控件统一**：所有输入、下拉、按钮同一套高度 / 圆角 / 焦点样式。

### 2.2 信息层级（每页三段式）

```text
第一层：这是什么      → 页面标题 + 一句业务化的副标题（≤40 字）
第二层：现在怎么样    → 结论 / 指标 / 状态筛选（一屏内可见）
第三层：怎么处理      → 清单、表格、缺口、入口
```

改版后的落点：

| 页面 | 第一层 | 第二层 | 第三层 |
| --- | --- | --- | --- |
| 总览 | 标题 +「按岗位、车型、学习阶段看是否可讲可考」 | 口径条（岗位 / 车型 / 学习阶段 / 优先级）→ 四指标条 → 一行辅线（内容待核、补学任务） | 待补缺口（可下钻）→ 两张热力图 → 折叠「业务环节对照」→ 折叠「数据校验」 |
| 知识点库 | 标题 +「全部知识点，先看红色缺口」 | 常用视图 + 4 个筛选 + 排序 | 清单（缺什么 / 负责人 / 操作） |
| 候选 | 标题 +「确认后才入库，相近的先并入」 | 待确认计数 + 全选 / 批量 | 候选表（相近提示 + 三个动作） |
| 补学进度 | 标题 +「谁还没补学」 | 4 张状态卡（可点筛选） | 状态页签 + 搜索 + 任务表（催办 / 关闭） |
| 知识图谱 | 标题 +「先看全貌，再看先后关系」 | 启用数 / 前置 / 相关 / 孤立 | 全貌（可切「只突出有缺口」）+ 单点关系 |
| 详情 | 面包屑 + 标题 +「能不能上课」结论条 | 四格状态 + 怎么补 | 核心讲解 → 核心测评题 → 过关演练 → 学员掌握度 → 其他系统测评 |
| 表单 | 面包屑 + 标题 + 分区导航 | 错误摘要（有错才出现） | 5 个分区顺序填写 |

### 2.3 操作路径（前后对比）

| 场景 | 改版前 | 改版后 |
| --- | --- | --- |
| 候选入库 | 一键生成残缺知识点 | 「补全并新增」→ 预填表单 → 必填校验 → AI 评估（可跳过）→ 保存后候选标记「已新增」并回链 |
| 候选去重 | 提示旧名、不能并 | 提示 v1.2 同名点并可点开；「并入已有」写入同义词并留痕 |
| 从总览找缺口 | 靠看热力格自己筛 | 缺口清单可直接点；热力格 / 「查看全部」带条件跳进知识点库 |
| 从列表进详情 | 点名称；翻页按全库顺序 | 整行可点；翻页按当前筛选后的顺序 |
| 补学跟进 | 只能看 | 状态页签 + 搜索；逾期的可「催办 / 关闭」，关闭需确认 |
| 详情补资源 | 缺口区与资源卡两处按钮 | 缺口区只做汇总与说明，补资源统一在资源卡（新增 / 添加已有） |

## 3. 布局结构

### 3.1 页面骨架

```text
┌ 内容区（max-width 1440，padding 24 28 40）──────────────┐
│ .ph        标题 + 副标题                    右侧主按钮  │
│ .tabs      页签（总览 / 知识图谱 / 知识点库 / 候选 / 补学）│
│ .ux-note   一句页面说明（替代全站横幅）                   │
│ 主体：口径条 / 指标条 / 卡片 / 表格                        │
└──────────────────────────────────────────────────────────┘
```

- 详情页沿用两栏 `.dgrid`：主区（左）+ 侧栏 320px（基本信息 / 知识关系 / 管理 / 变更记录）。
- 表单页沿用 `.frm` 两列（标签 130px + 控件），分区之间用 `<section>` 分隔，`scroll-margin-top:54px` 让吸顶栏不遮挡标题。

### 3.2 关键组件结构

**指标条（.ux-metrics）**：4 等分，中间画分隔线；每格 = 名称 13px / 数值 28px / 说明 12px。≤1100px 折成 2×2。

**口径条（.ux-bar）**：左侧 4 个筛选（岗位 / 车型 / 学习阶段 / 优先级），右侧一句「当前口径下应覆盖 N 个知识点」。

**缺口清单**：知识点（名称 + 编号 · 知识域 · 优先级）/ 缺什么（标签）/ 负责人 / 去补。最多 8 行，超出给「查看全部 N 条 ›」。

**候选表固定列宽**：选择 32 / 候选 170 / 来源 120 / 为什么（自适应）/ 状态 110 / 操作 250，`table-layout:fixed`，操作按钮不换行。

**补学任务表**：人 / 门店（两行）/ 知识点（名称 + 编号 · 版本）/ 级别（L2 · 口径变更）/ 状态 / 截止（+ 还剩 N 天）/ 最后动作 / 操作。

### 3.3 响应式

- ≥1100px：指标 4 列、详情两栏。
- 820–1100px：指标 2 列、详情侧栏落到主区下方。
- <820px：表格横向滚动（`.tw`），不隐藏列。

## 4. 交互规则

### 4.1 列表与详情

1. 整行可点 → 进详情；行内「查看 / 编辑」仍独立可用。
2. 从列表进入详情时记录当前列表顺序，`上一个 / 下一个` 按该顺序翻；直接打开详情则退回全库顺序。
3. 默认排序：缺口优先（P0 且缺讲解 > 其他缺口 > 完备）；可切「优先级」「名称」。
4. 「缺什么」列最多显示 3 个标签，多余折叠为「等 N 项」；判定口径与详情结论条、总览缺口清单同一个函数 `kpGapList`。
5. 筛选条件「清除筛选」在无筛选时置灰；「更多筛选」显示已选项数。

### 4.2 下钻

- 热力格点击 → 带「车型 + 卖点分类 / 能力项 + 当前优先级」跳知识点库。
- 「查看全部 N 条」→ 带「未完备 + 当前口径」跳知识点库。
- 补学进度状态卡 / 状态页签 → 同页筛选，不跳页。
- 候选「相近知识点」→ 直接打开该知识点详情。

### 4.3 表单

1. 必填项：知识点名称、适用车型、适用岗位、知识域、知识点类型、卖点分类（产品知识）或能力项（非产品知识）。
2. 分类类必填项默认显示「请选择」（disabled selected），必须由人主动选择；`填过` 后不再回退占位。
3. 校验时机：点保存时统一校验；失败时
   - 顶部出现错误摘要（列出全部问题，点击跳到对应字段）
   - 字段标红、标签变红、正上方给出具体原因
   - 首次报错字段自动滚动到视口中央
4. 新增且未做 AI 评估时，保存前弹一次确认：「仍然保存 / 先去评估」；编辑不拦。
5. 吸顶栏左侧显示「新增知识点 / 编辑知识点」+ 当前名称（未填时显示「尚未填写名称」），右侧取消 / 保存。
6. 分区导航吸顶：1 定义与边界 / 2 谁需要、用在哪里 / 3 怎样算学会 / 4 谁负责、何时复核 / 5 学习先后与关联。
7. 从候选进入时，表单顶部提示来源，保存后候选自动标记「已新增」并回链。

### 4.4 候选

- 三个动作：补全并新增（主）/ 并入已有（次，无相近点时禁用）/ 忽略（次）；「发起评审」为文字链。
- 有相近点时在「为什么要加」下方给出黄色提示，并可直接打开该知识点。
- 批量：确认新增生成的仍是「停用草案」，界面明示需要逐个补全后启用；评审中的候选仍被拦截。

### 4.5 补学任务

- 状态由「截止日 + 演示日期」推导：已复测 / 已关闭 / 挂起 保持；其余截止日已过 → 逾期，未过 → 未读 / 已读 / 已确认。
- 截止列显示「还剩 N 天 / 今天截止 / 已逾期 N 天」。
- 进行中：催办（记录时间，不向学员推送）、关闭（二次确认）。
- 统计卡与页签数字同源（`kpTaskStats`），人员数按任务去重。

### 4.6 状态约定

| 状态 | 触发 | 组成 | 出口 |
| --- | --- | --- | --- |
| 空 | 查询结果为 0 | 标题 + 说明 | 按上下文给 1–2 个动作（清除筛选 / 新增 / 看全部） |
| 空（无数据） | 对象集合本身为空 | 同上 | 引导创建（新增知识点 / 批量导入） |
| 报错 | 渲染异常、对象不存在 | 标题 + 说明 + 技术原因（小字） | 重试 / 返回知识点库 |
| 加载 | 异步操作进行中 | 一句进度说明 + 骨架条（`.ux-live` + `.ux-skel`） | 完成后原地替换；失败给可重试提示 |

加载态接在唯一真实的异步路径上：知识点「批量导入 / 新车克隆」读取 CSV 文件（`FileReader`）期间显示「正在读取 xxx.csv…」+ 骨架条，读完由导入结果替换；读取失败提示换 UTF-8 或直接粘贴。其余 Demo 数据是同步生成的，不假装加载。

## 5. UI 规范

### 5.1 色板

| 用途 | 变量 | 值 |
| --- | --- | --- |
| 主色（主按钮 / 链接 / 选中） | `--pri` | `#ff6700` |
| 主色浅底 | `--pri-l` | `#fff4ec` |
| 成功 | `--ok` | `#12a36b`（底 `#e7f8f0`，字 `#0b7a50`） |
| 警示 | `--warn` | `#d98a00`（底 `#fff4d6`，字 `#8a5200`） |
| 错误 | `--err` | `#e5484d`（底 `#fdecec`，字 `#b42318`） |
| 正文 | `--ink` / `--ink2` | `#101828` / `#344054` |
| 次要 / 弱化 | `--sub` / `--mut` | `#667085` / `#98a2b3` |
| 描边 / 分隔 | `--bd` / `--bd2` | `#eaecf0` / `#d0d5dd` |

规则：一屏最多一个主按钮（橙色实心）；状态只用上面三组色，不做渐变、不用彩色描边强调。

### 5.2 字体

| 层级 | 字号 / 字重 |
| --- | --- |
| 页面标题 | 22px / 650 |
| 卡片标题 | 15px / 650 |
| 指标数值 | 28px / 650（`letter-spacing:-.5px`） |
| 正文、表格 | 13.5–14px / 400 |
| 表头、筛选标签 | 12px / 600（表头）/ 400（标签） |
| 辅助说明 | 12px / 400（`--mut`） |

数字统一用等宽感（表格内数值右对齐时同宽），中英文混排不加空格。

### 5.3 间距与圆角

- 栅格间距 16px；卡片内 20–22px；表格行 12px × 14px。
- 圆角：卡片 12px，按钮 / 输入 8px，标签 999px，小按钮 7px。
- 分隔线统一 `1px --bd`，不用粗线，不用阴影分隔（仅卡片 1px 阴影）。

### 5.4 控件

| 控件 | 规范 |
| --- | --- |
| 按钮 | 高 34px（小号 28px），左右 14px（小号 10px），8px 圆角；主按钮橙色实心，次按钮白底描边，文字链用于第三优先级 |
| 输入 / 下拉 / 文本域 | 高 34px，8px 圆角，描边 `--bd2`，聚焦 `--pri` + 3px 淡橙光圈；占位文案是示例值，不带「请输入」 |
| 复选 / 单选 | 原生控件，标签 13px，间距 8×16 |
| 页签 | 灰底容器内白色选中块，13.5px |
| 吸顶操作栏 | 白底 + 顶部 1px 描边，左侧标题 + 当前对象名，右侧动作，高度 56px |

### 5.5 表格

- 表头 12px / 600 / `--sub`，灰底（`#fafbfc`），行悬停 `#fcfcfd`。
- 首列左内边距 14px；数字列右对齐；状态列不换行；长文本列允许换行并给最小宽度。
- 操作列固定在最后一列，按钮与文字链间距 6px；列数超过 8 列时只保留 6 列（精简视图），其余用「完整字段」展开。
- 状态标签：`ok / warn / err / blue / 默认` 五类，高度 22px，12px 字，不加图标。

### 5.6 文案

- 说结果不说机制：用「可考核率」「核心测评题 0/3」「已逾期 3 天」，不用「分母」「进分子」「error / warn」。
- 禁用开发词：分母、分子、口径应为、error、warn、v1.2 总览。
- 技术字段不上主界面：`document_id` 写成「依据资料 ID」并在说明里解释用途。
- 每个空 / 错状态必须回答三件事：发生了什么、为什么可能发生、下一步点哪里。
